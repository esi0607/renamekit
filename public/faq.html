파일명 바꾸기

자주 묻는 질문

최종 수정 2026년 10월 28일

실제로 가장 많이 들어오는 질문 15개를 모았습니다. 여기에 없는 내용은 사용법 문서를 먼저 확인해 주세요.

기본

1. 파일이 서버로 올라가나요?

아니요. 압축 풀기, 이름 변경, 다시 압축하기까지 전부 브라우저 안에서 처리됩니다. 파일 내용이 네트워크로 전송되는 코드는 들어 있지 않습니다. 개발자 도구의 네트워크 탭을 열어두고 사용해보면 전송이 없다는 것을 직접 확인할 수 있습니다.

2. 설치가 필요한가요?

필요 없습니다. 브라우저로 주소를 열면 바로 쓸 수 있습니다. 프로그램 설치나 회원가입도 없습니다.

3. 무료인가요?

모든 기능이 무료입니다. 운영 비용은 사이트에 표시되는 광고로 충당합니다.

4. 인터넷이 없어도 되나요?

페이지를 한 번 연 뒤에는 대부분의 기능이 동작하지만, 브라우저가 캐시를 비우면 다시 접속해야 합니다. 파일 처리는 네트워크와 무관합니다.

파일과 압축

5. zip 없이 파일만 넣어도 되나요?

됩니다. 파일 여러 개를 그대로 끌어다 놓으면 이름을 바꾼 뒤 zip 하나로 묶어서 내려받게 됩니다.

6. 폴더 구조가 유지되나요?

유지됩니다. zip 안의 하위 폴더는 그대로 두고 파일 이름만 바뀝니다. 사진/IMG_0001.jpg는 사진/photo_001.jpg가 됩니다.

7. 암호가 걸린 zip도 되나요?

안 됩니다. 암호를 푸는 기능은 넣지 않았습니다. 압축을 먼저 푼 뒤, 폴더째 다시 zip으로 묶어서 사용해 주세요.

8. 7z나 rar 파일도 되나요?

zip만 지원합니다. 7z·rar·alz는 브라우저에서 다루기 어려워 대상에서 제외했습니다. 반디집 같은 프로그램으로 zip으로 변환한 뒤 사용해 주세요.

9. 4GB가 넘는 zip도 되나요?

ZIP64 형식은 아직 지원하지 않습니다. 브라우저 메모리를 쓰는 구조라 4GB 이상은 어차피 현실적으로 어렵습니다. 500MB 이하를 권장합니다.

10. 파일이 몇 개까지 되나요?

개수 제한은 없지만, 1,000개를 넘으면 미리보기 표시가 느려집니다. 아주 많을 때는 폴더 단위로 나눠서 처리하는 편이 안전합니다.

한글과 파일 이름

11. 한글 파일명이 깨지지 않나요?

윈도우에서 만든 zip은 파일명을 CP949로 저장하는 경우가 있습니다. 이 도구는 zip 항목에 UTF-8 표시가 없으면 CP949로 다시 읽어서 한글이 깨지지 않게 처리합니다. 다만 아주 예외적인 방식으로 만들어진 zip은 실패할 수 있습니다.

12. 이름이 너무 길면 어떻게 되나요?

윈도우는 경로 전체 260자, 맥은 파일명 255바이트 제한이 있습니다. 미리보기에서 이름이 잘린 줄에는 확인 표시가 붙습니다. 길이 자르기 규칙으로 미리 줄여두면 안전합니다.

13. 확장자도 자동으로 바뀌나요?

아닙니다. 확장자는 확장자 변경 규칙으로만 바뀝니다. 다른 규칙은 확장자를 건드리지 않습니다. 이렇게 설계한 이유는, 실수로 확장자가 사라져 파일이 열리지 않는 사고를 막기 위해서입니다.

14. 이름이 중복되면 어떻게 되나요?

미리보기에 오류로 표시됩니다. 그 상태로 내려받으면 한 파일이 사라질 수 있으니, 오류가 없는 상태에서만 다운로드하세요. 보통 번호 매기기 규칙을 넣으면 해결됩니다.

정렬과 번호

15. 자연순과 원본순은 무엇이 다른가요?

자연순은 사람이 읽기 좋은 순서로, 숫자를 크기대로 비교합니다 (1, 2, 3, 10). 원본순은 zip 안에 실제로 저장된 순서입니다. 번호 매기기는 화면에 보이는 순서를 따르므로, 번호가 1, 10, 2처럼 붙는다면 정렬이 원본순으로 되어 있는지 확인해 보세요. 기본값은 자연순입니다.

개인정보와 광고

광고와 쿠키는 어떻게 되나요?

사이트 운영을 위해 Google AdSense 광고가 표시될 수 있고, 이 과정에서 Google과 제3자 판매자가 쿠키를 사용합니다. 자세한 내용과 거부 방법은 개인정보처리방침에 정리해 두었습니다. 파일 내용은 광고와 무관하게 어디에도 전송되지 않습니다.
